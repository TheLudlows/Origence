# AML 同预算比较 v1

执行前冻结见 [freeze.json](freeze.json)。本轮依次完成长消息定位校验、配置冻结、v4 32 题与公开 LongMemEval 32 题比较，再作接入决策。三臂为原文 vector、原聊天重排、固定本地 BGE；均无扩展/摘要/图。

共同 top-100 原始召回按顺序最多取 40 条、8,000 个参考 tokenizer token、32,000 UTF-8 bytes；最终证据最多 5 条、2,000 参考 token、9,000 bytes。预算计算含序列化证据元数据；达到上限停止取后续条目，不截断原文。参考 token 使用已固定 BGE tokenizer，不冒称 Qwen token；供应商实际用量另记。限额是相同上限，并不强行填满各臂上下文。BGE 每对上限从历史实验的 512 显式改为 1,024，不截断；超限作为错误。

固定原 Answer 提示词；public 另提供问题日期。金标准仅进入离线评分。匿名化臂顺序的同 Qwen 裁判检查实体、时间、合取条件、严格边界、计算/多跳与引用支持。v4 另要求所有必要消息完整引用；public 只有会话级标签，所以只报告 session recall，不能宣称完整证据 recall。运行/裁判错误保留在分母。没有独立人工复核，不是官方 AML 或完整 LongMemEval 成绩。

公开 1,524 批/15,685 条消息均保留，32 个问题各自独立用户，绝不合并共享历史的用户语料；共享会话仅用于分组统计，10 个连通分组大小为 15、8、2、1、1、1、1、1、1、1。数据日期未指定时区，统一按 UTC 编码是明确适配约定，不宣称真实时区。v4 按 16 个题对分组，开发/新主题分别单列。原冻结语料和历史工件不改写。

阶段：retrieve → prepare → rank(chat/bge) → answer(vector/chat/bge) → grade。每阶段独占创建压缩报告，失败保留且不自动重试；上游工件及冻结输入校验 SHA-256。预定最多 320 次聊天调用，每个独立阶段最多 60 次、单次 60 秒、temperature=0、无 thinking、最多 2,048 输出 token。服务/域名/官方 Smoke 后置。

接入门槛在运行前写入 freeze：全部成对安全用例通过、每个划分的受支持成功率不低于聊天重排、无来源/执行错误、重排额外延迟 p95 ≤3秒；本地 BGE allocator 峰值≤3GiB（不代表整机显存/内存）。小样本、宽区间与独立人工复核缺失仍限制生产结论。

## v4 初步结果及评分审计

冻结的同模型裁判原始成功计数：开发 vector/chat/BGE 为 16/16、15/16、16/16；新主题为 15/16、14/16、15/16。三臂可答题的必要消息覆盖均为 100%，所以这组短消息并未显示检索缺证据差异。共 160 次聊天调用，供应商报告 126,798 token；无检索/回答/裁判执行错误。

逐条阅读 96 个回答及失败裁判后，发现 [评分争议](v4-semantic-audit.json)：问题已给出单位时的简答被误扣分、问题中的边界措辞可由回答继承，以及“哪里维修”可由店名作答但标签强制要求地址。这些分数保留，不事后改题、删除失败或重算漂亮成绩；不据此宣布 BGE 胜出，也不能据此指控三臂编造维修地点。尚需独立复核与明确题意的新版本。

BGE 重排额外耗时 p50/p95 为 35.24/56.64 ms，聊天为 659.86/3069.97 ms；本次证据都很短，且有公开数据入库及远端调用重叠，不能与上一轮 100 候选推理直接比速。BGE allocator 峰值 1,174,276,096 bytes。

本轮来源索引要求每个 (user_id, session_id) 只有一个 Add 批次，重复键直接报错；公开选中会话均不超过 256 条消息，因此无需拆批。产品仍以稳定 chunk UUID 区分来源；本实验不宣称已适配同一会话跨多个 Add 批次的外部语料。

## 完整公开结果与最终决策

64 道题、两个数据集的全部阶段完成；[统计](summary.json)、[16 份阶段工件完整性检查](integrity-audit.json)、[公开失败审计](public-semantic-audit.json)。全轮 320 次聊天调用，供应商报告 477,289 token，无缺失 usage、无模型自动重试、无检索/回答/裁判执行错误；两次临时宿主目录均清理。没有官方 AML 分数。

Top-100 会话 Recall 98.28%，共同候选池 97.59%；最终预算下均有损失。BGE 命中会话比例稍高，并未变成更高答题成功率。BGE−聊天成功率差的 10 分组 bootstrap 区间为 −16 到 +25 个百分点，不能确定优劣。单臂描述区间 vector 50.0%–81.8%、聊天 33.3%–81.6%、BGE 41.2%–76.6%；分组少且很不均衡。v4 全成功子集的 bootstrap 退化为 [1,1] 也不意味着总体成功概率为 1。

性能：公开 Search p50/p95 5143.35/5289.27 ms；重排额外耗时聊天 906.76/1412.71 ms、BGE 353.48/511.57 ms。模型加载另记，BGE allocator 峰值 1,312,226,816 bytes，每对实际最大 857 tokens，未截断。每个公开候选池实际 18–37 条；共同预算是上限，不等于三臂最终 token 完全相同。并发情况见 [运行说明](runtime-notes.json)，不宣称生产 SLO 或整机内存上限。

人工方式逐条阅读由同一 agent 完成，不是独立人工复核。公开裁判暴露出四类问题：有明确算术支持却被标 unsupported；引用 2月10日航班却放行为情人节事件；历史 today 被阅读器当提问当天、裁判又标 supported；一道公开参考值与 gold 会话日期冲突，裁判还算错 epoch。原始分数全部保留，没有删题、修改标签、根据结果改参数或重新评分。

**决定：生产 Search 保持原文 vector；聊天重排、本地 BGE、同模型核验均留实验层。** 来源/预算/执行门槛通过，但质量非劣未证实，成对安全门槛受题意和标签歧义影响不能验收，同模型裁判存在明确错判。BGE 的资源和延迟优势支持继续作为成本候选，不能据此替代现有路径；聊天重排也未获得稳定公开收益。

下一项先做时间来源可读化与日期运算的独立消融、修正并独立复核下一版问题/rubric、校准裁判的错误放行与错误拦截；同时对 top-100 Search 约 5.3 秒做本地分段性能定位。先定位再优化，不预设数据库或 embedding 是原因。当前 64 题以后只作已观察回归，不再称未见验收；不得把 gold 数据带入可部署检索或答案核验。服务器、域名与官方 Smoke 继续后置。
