# AML 本地检索 v2：较长历史与近似干扰

自编合成数据，不含官方 AML 题目。共 2 用户、32 会话、512 条短消息、30 道问题。每个用户有 256 条消息，相关事实分布在历史前中后部；这验证比 v1 更长的消息历史，不等同于长消息分块、真实长上下文或长期容量验证。

## 预先冻结

[freeze.json](freeze.json)在第一次运行前记录语料和 runner SHA-256、BGE-M3/1024 维、top_k=100、1/5/10/100 截断及关闭摘要/图。运行不调参；观察结果后不修改题目、标签或门槛。当前版本原文只包含自然语言消息，没有评测标签。

开发集为 workshop 设备项目：15 题，12 可答、3 无答案。留出集为 gallery 展览：15 题，11 可答、4 无答案。用户、session 和原文完全分离；两边均由同一 agent 编写且未经独立人工复核，仍有生成风格和题型相关性，不能声称是独立策划的真实评测集。全部来源在 Search 前写入，尚无 streaming/未来可见性测量。

干扰包含相似但不同的活动、协议号/封签号、旧安排与更新、历史负责人与现任负责人、不同单位与含/不含附属物的重量。多跳标签要求 2–3 条证据同时出现。历史时间和当前状态问题衡量正确来源是否召回，不衡量模型是否正确选用事实。无答案统计仍只记录候选是否非空。

## 运行

沿用 [本地模型环境](../../../docs/AML_DRILL.md)，输出文件必须不存在：

~~~powershell
python tools/aml_quality.py --dataset v2 --binary target/debug/origence.exe --report target/aml-quality-v2-new.json
python -m unittest discover -s tools -p 'test_aml_quality.py' -v
~~~

runner 默认仍为 v1，旧语料和历史工件不变。报告新增 dataset/by_split，保留逐题原始响应、来源检查和同样的指标定义。不可直接拿两版分数差异证明算法退步或改善，因为语料发生变化。
