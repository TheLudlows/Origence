# AML 时间、裁判与检索耗时诊断

2026-10-11，基于 main 737e209。历史 budget-v1 保持不变；本目录是已观察回归上的独立诊断，不是新的未见评测或官方 AML 成绩。正式 Search 仍为原文 vector，不接入日期推理或裁判。

## 时间消融

[调用前冻结](freeze.json)选择原公开 32 题中的全部 10 道 temporal-reasoning 题，复用相同 vector 最终证据、顺序和 Answer 提示词。三个输入臂：raw 原输入；dates 另加 ISO UTC 消息日期；offsets 再加问题到消息、消息对之间的有符号日历日期差。日期是旁注，原始证据和引用不改；不将消息时间推断成事件时间。UTC 沿用原公开适配约定，不声称数据原生时区已知。新增旁注增加实际上下文长度，因此不是等实际 token 比较。

30 次 Answer 无执行错误。关键观察：

- herbs：raw 0 天、dates 2 天、offsets 3 天。4 月 15 日到 18 日为 3 个日历日；消息时刻到提问时刻只有 2 个完整 24 小时。日期辅助修复了本题按参考日历口径的答案，也暴露了“日历日/满 24 小时”的契约歧义。
- flu/jog：raw 10 周，dates/offsets 12 周；原文日期相隔 81 个日历日，12 周只是取整，公开参考 15 周仍有冲突。保留争议，不给这个结果补判成功。
- Valentine's flight：dates 拒答，raw/offsets 仍引用错误事件或缺航空公司名称的片段作答。日期差辅助没有解决事件对应。
- 两道事件排序/显式日期差题三臂保持答案；五题三臂均拒答。完整逐题边界见[语义审计](semantic-audit.json)。

## 裁判校准

12 个自建样例各 4 个 supported、contradicted、insufficient，覆盖单位、严格边界、日期、算术、错事件、缺链和不完整证据。旧裁判沿用原提示词与参考答案结构；新裁判只接收问题、待核答案和引用，不接收参考答案，独立判断证据支持。两种裁判都使用 qwen3.8-flash，作者与审阅者均为同一 coding agent，未经独立人工复核。

| 指标 | 旧裁判 supported 字段 | 新支持分类器 |
| --- | --- | --- |
| 支持/不支持与自建标签一致 | 8/12 | 11/12 |
| 错误放行 | 4/8 不支持样例 | 1/8 不支持样例 |
| 错误拦截 | 0/4 支持样例 | 0/4 支持样例 |
| 三分类一致 | 不适用 | 11/12 |

不能把表格解释成端到端胜出：旧裁判的 correct AND supported 联合结果在这些负例上是 0 次错误放行。新分类器仍把“6−2 应为 4、回答 6”标为 supported，尽管解释否定了答案。记录原始结构化字段，不从理由文本事后修分。因此它仍不能作为可靠门禁。

54 次模型调用共 53,719 个供应商报告 token、191,501 输入 UTF-8 字节，无重试或执行错误。[离线审计](audit.json)重建了 30 份模型输入、引用、日期旁注与 24 个校准结果；[原始运行](run.json)保留所有字段。

## 性能诊断

生产代码仅新增默认关闭的聚合 debug 计时，不改排序、权限、原文、解析器或 API 返回。[单历史测量](search-profile.json)选择已观察 32 题中原始 UTF-8 总字节最大的历史：46 批、502 条消息、503,680 字节。真实本地 BGE-M3 Add 完成后，同一问题按 top-k 5/100 交替测 8 次，验证原文字节、用户范围与重复 ID 稳定，宿主和临时目录均回收。

单历史 HTTP 约 611–760 ms，向量阶段 508–591 ms，嵌入 17–55 ms，最终权限/身份复核在 top-100 时约 21–44 ms。第一请求保留，不当作热态样本。这没有复现上轮完整多用户库约 5 秒耗时，不能宣称已优化或问题已解决。[调用前规模计划](search-scale-plan.json)在四个其他用户下新增 512 个单消息批次后，[同一查询](search-scale.json) HTTP 变为 2143–2312 ms，向量阶段 1992–2127 ms。向量请求数仍为 2、原生候选数仍为 163。额外成本集中在向量后端，支持继续排查共享表规模/碎片影响；尚未区分打开表、manifest/schema 与过滤扫描。两个宿主的 UUID 不同，未宣称跨宿主 ID 相同。所有 16 次搜索均通过范围/字节检查及各宿主内部稳定性校验；两个临时目录已清理。[汇总](search-comparison.json)。

均为 Windows、debug 构建、单查询并发，无索引或缓存优化，不是生产 SLO。Rust 验证与 Python 回归可能在规模对照入库期间运行；检索阶段单独测量。单历史首次 Python 测试也可能与入库重叠。精确机器/模型继承 budget-v1，本轮未更换模型或依赖。首版性能执行器已归档为 search-profile-runner-v1.py.gz，后续版本仅增加可控背景写入。

## 复现与后续

固定调用脚本默认独占创建 run.json，防止覆盖。模型凭据只从环境读取。离线验证使用 python tools/aml_temporal_verify.py；已有 audit.json 时应导入 verify() 而不覆盖。性能测量使用 python tools/aml_search_profile.py --binary target/debug/origence.exe --report 新文件，可加 --background-batches 512。外部宿主进程用于真实 HTTP 测量，生命周期沿用既有 Host；业务库未引入子进程。

下一步是明确日历/持续时长及取整契约、用独立标签验证事件对应和裁判一致性，并根据规模对照细分向量后端耗时。时间旁注与新裁判继续留在实验层；服务、域名与官方 Smoke 后置。
