## Capabilities and verification limits

| Capability | Available operations and requirements | Verified and pending |
| --- | --- | --- |
| Explicit memory and controlled extraction | Use Memory Management, `POST /v1/memories/semantic`, or `POST /v1/captures/semantic`. Extraction requires a writer, an extraction model, and identities selected by the caller. Differing extracted values for an existing single-valued fact are kept as separate evidence. Explicit confirmation can publish a new current version. | Engineering tests cover concurrency, replay, conflict retention, and source withdrawal. Extraction accuracy awaits measurement. [Memory contract](contracts/memory.en.md) · [Controlled extraction](contracts/semantic-capture.en.md) |
| Long-term memory and experience | `context_memory_retain` accepts source text for facts or starts experience verification from feedback in the caller's private session. Readers can use `context_memory_recall` with `query` to retrieve facts and published experience together by term. Fact timelines, versions and sources are accessible by full identity or ID. | Synthetic model tests cover effective times, conflicts, experience conditions, authorization and withdrawal. Term matches are marked `unverified`. Live model quality and cross-session benefit await verification. [Long-term memory contract](contracts/memory-consolidation.md) |
| Knowledge and task context | Ingest Text, Markdown, or PDF, read specified versions, withdraw sources, and locate passages. `POST /v1/context` and `context_bundle` use the business time in `as_of_ms` to recall consolidated facts with timelines and source citations. Run preparation rejects explicit `as_of_ms`. | A synthetic reimbursement case verified dates, conflicts, budgets, fixed citations, and withdrawal through real HTTP, MCP, and Chromium. Real-task quality and latency at scale await acceptance. [Context contract](contracts/evidence-bundle.md) |
| Private turns and feedback | Writers can archive turns explicitly. Codex and Claude Code support per-project incremental sync, disabled by default. The current logical key can recall turns through the `session` route in `context_bundle`. Synced turns record evidence use as `unknown`, and Improve skips them. | Explicit archiving has engineering evidence from both clients. Synthetic hooks and real HTTP verified redaction, isolation, and replay for incremental sync. Native sync on both clients and the Windows/macOS paths await verification. [Client integration](CLIENTS.en.md) |
| Skill | In Run details, the owner selects an ending event and manually drafts, edits, and submits a candidate bound to that prefix. Review, approval, and explicit publication use the CLI or API. Published packages can be exported to both clients. | Synthetic tests cover fixed prefixes, idempotent retry, invalidation after edits, authorization and withdrawal. Separate public examples demonstrate native loading in both clients. Reuse on unseen tasks awaits #91. [Candidate workflow](SKILL-CANDIDATE-CLI.md) |
| Trace and metering | Both plugins install structured Run Hooks by default. The console shows private Runs, fixed citations, coverage declarations, external assessments and usage received from executors. | Synthetic engineering checks used both native clients for installation and default Hooks. Full event coverage, live whole-run usage, and independent business outcomes await acceptance. [Run contract](contracts/runs.md) |
| Administration and access | Account sign-in, workspace grants and creation, and API key management are available. One logical key can be granted access to multiple workspaces. Select the workspace in the HTTP request or when opening an MCP connection. `origence-setup` connects agents and `origence-deploy` provisions local services. | Console workspace switching and native plugin installation have been verified. In-session switching in native agents, enterprise identity, and per-document access rules remain gaps. [Installation](INSTALLER.en.md) · [Workspace status](STATUS.en.md) |

## Retrieval baseline and formal acceptance

- [#163](https://github.com/TheLudlows/Origence/pull/163) restored default AND matching. Every query term must appear in the same indexed chunk. This also applies to the keyword branch of hybrid retrieval. All eight real AnySeek contract tests passed. [The OR experiment in #154](https://github.com/TheLudlows/Origence/pull/154) serves as a historical comparison. [Retrieval contract](API.en.md#retrieval)
- The [#152 Chinese document benchmark](https://github.com/TheLudlows/Origence/issues/152#issuecomment-7192373228) used 36 synthetic documents and 300 questions on `13e2a4c`. Origence achieved 97.57% source Recall@5 (281/288) and returned candidates for 12/12 unanswerable questions. The [cross-session checkpoint](https://github.com/TheLudlows/Origence/issues/152#issuecomment-7193961142) ran 21 integration questions. Answer accuracy and abstention on the full 500-question set await measurement. Each result applies to its recorded revision and configuration.
- [The formal pilot in #91](https://github.com/TheLudlows/Origence/issues/91) remains `NOT_RUN`. Engineering troubleshooting and reimbursement review have public synthetic exercises. The formal freeze still requires approved unseen questions and materials, model revisions and budget, and independent reviewers including a DBA and the policy owner. [Freeze readiness](../evals/pilot/FREEZE-READINESS.md)
