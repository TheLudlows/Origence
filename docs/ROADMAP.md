# Origence · 产品目标与长期路线图

**简体中文** · [English](ROADMAP.en.md)

**Origence 是面向智能体的统一数据底座，涵盖记忆、知识、Skill 和 Trace。** 智能体可以读取符合当前任务与权限的数据，也可以提交任务记录，让用户查证结果并决定哪些经验值得复用。

本文描述产品目标与阶段验收。首版面向企业研发与业务团队，在内网以 Claude Code 和 Codex 试点。首版技术合同、当前实现进度和具体验证分别见[架构规划](design/agent-data-foundation.md)、[STATUS](STATUS.md) 和 [VALIDATION](VALIDATION.md)。

## 核心数据

| 数据 | 管理什么 |
| --- | --- |
| 记忆 | 项目事实、偏好、决策和可复用经验，带适用条件、版本及来源。 |
| 知识 | 文档、团队规范和业务资料，支持发布、更新、撤回和精确版本引用。 |
| Skill | 可复用的方法、流程和参考资料。选定经历可形成候选，经有发布权的人批准精确版本后共享。 |
| Trace | 以 Run 组织运行证据，记录服务端准备的上下文、客户端报告的 Skill 加载、工具与结果、采集缺口和外部核验。 |

## 数据如何使用

- **检索与上下文组装**按任务、权限和预算选择证据，并在指定 Run 中记录上下文准备结果。
- **私有归档与经验沉淀**保存明确提交的问答和反馈。同一逻辑 key 可查询自己的归档。通过显式 Improve 流程，符合条件的反馈可形成 Learning，选定经历可以作为 Skill 候选的依据。
- **追溯与评估**用 Trace 核对具体任务的运行证据，用固定任务比较版本与效果。事实维护、知识发布和 Skill 审阅可以独立进行。

平台通过 HTTP、MCP 和管理界面提供相应入口。归档、私有 Run 和未发布候选按逻辑 key 隔离。已发布的记忆、知识和 Skill 归 workspace，由获授权成员使用，并遵守来源、版本和撤回规则。

## 分阶段推进

| 阶段 | 优先交付 | 何时算达到阶段目标 |
| --- | --- | --- |
| **P0 · 内网试点** | Claude Code / Codex 私有归档与隔离；事实更正、知识发布与撤回；反馈形成 Learning，选定经历生成候选并审阅发布；Run 连接交付与核验。 | 同一版本完成数据库排障和报销复核两类真实客户端试点，核对精确引用、实际 Skill 加载、隔离与撤回，并由独立人员签认。导出、客户端自报或脚本绿灯不能替代验收。跟踪见 [#91](https://github.com/TheLudlows/Origence/issues/91)。 |
| **P1 · 分析与评估** | 建立冻结评测集，补齐分层调用、重试、聚合与可采的实际用量和成本；改善原文定位与治理操作。 | 同题对照可复算，分别报告任务成功率与证据核验覆盖，保留配置、版本和分母；计量未采集标为未知，不填零。 |
| **P2 · 扩展与自动提炼** | 按需求扩展宿主和外部遥测，探索跨 Run 自动提出候选、版本回归告警、企业身份及更细粒度的来源授权。 | 有明确业务负责人和足够已核验样本，能评估候选质量、误报和人工纠正成本；验证撤权与跨工作空间隔离。自动产生候选不等于自动发布。 |

阶段推进以数据可靠性、经验复用和任务效果为依据。新增宿主、度量和自动化沿用上述授权和证据要求。

## 边界与待决事项

- 智能体宿主负责推理、任务编排和业务工具执行。Skill 发布和工具执行分别受各自的授权约束。
- 沿用 [SQLite 权威数据、AnySeek 检索、Blob 原始文件](design/agent-data-foundation.md) 的分工，不在此路线图另起检索或数据库内核。现阶段以新建数据库为目标，同版本恢复仍要验证。
- 托管部署、生产成本阈值、ContextBase 互通与 Agent one 接入按需求另立决策，不视为已承诺的交付项。
