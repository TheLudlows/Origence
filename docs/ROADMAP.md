# Origence · 产品目标与长期路线图

Origence 是面向企业研发与业务 Agent 的数据和知识底座。它保存个人任务经历，管理团队确认过的事实、知识和工作方法，在下一次任务中交付有权限、有来源、适用当前场景的上下文。任务结束后，团队能追溯实际交付了什么、客户端报告使用了什么、结果如何被核验，并决定哪些经验值得复用。

本文依据产品需求 v0.3 整理，描述目标和阶段验收，不是已交付清单或日期承诺。首版技术合同见[架构规划](design/agent-data-foundation.md)，实现进度见 [STATUS](STATUS.md)，具体验证见 [VALIDATION](VALIDATION.md)。

## 六项产品能力

| 能力 | 解决什么问题 |
| --- | --- |
| 私有会话与任务归档 | 保留明确提交的问答、反馈与任务记录，让同一逻辑身份跨客户端找回自己的归档，不恢复客户端工作现场。 |
| 长期记忆与事实 | 保存确认过的项目事实、偏好和决策，记录适用条件、版本、更正与来源。 |
| 文档与知识 | 发布、更新和撤回可定位的团队规范与业务资料，保留原始文件和精确版本引用。 |
| 经验学习与 Skill | 从有依据的反馈形成 Learning；从选定经历生成可编辑候选，由有发布权的人审阅并批准精确版本后共享。 |
| Agent Context Engine | 按任务、权限和预算检索与组装证据，交付精确版本并保留准备回执。 |
| Agent 可观测与评估 | 按 Run 串联上下文、客户端报告的 Skill / 工具 / 结果、采集缺口和独立核验；用固定任务比较版本与效果。 |

Context Engine 负责准备与交付，可观测性负责记录与核对，两者在同一 Run 的证据上相交。事实维护、知识发布和 Skill 审阅也能独立发生，不需要先有一条 Run。

六项能力共用工作空间、逻辑 key、证据版本、来源和撤回规则，通过 HTTP、MCP 和管理界面接入。个人归档、私有 Run 和未发布候选不因 workspace 成员身份而共享；已发布资产只向获授权成员提供。

## 分阶段推进

| 阶段 | 优先交付 | 何时算达到阶段目标 |
| --- | --- | --- |
| **P0 · 内网试点** | Claude Code / Codex 私有归档与隔离；事实更正、知识发布与撤回；反馈形成 Learning，选定经历生成候选并审阅发布；Run 连接交付与核验。 | 同一版本完成数据库排障和报销复核两类真实客户端试点，核对精确引用、实际 Skill 加载、隔离与撤回，并由独立人员签认。导出、客户端自报或脚本绿灯不能替代验收。跟踪见 [#91](https://github.com/TheLudlows/Origence/issues/91)。 |
| **P1 · 分析与评估** | 建立冻结评测集，补齐分层调用、重试、聚合与可采的实际用量和成本；改善原文定位与治理操作。 | 同题对照可复算，分别报告任务成功率与证据核验覆盖，保留配置、版本和分母；计量未采集标为未知，不填零。 |
| **P2 · 扩展与自动提炼** | 按需求扩展宿主和外部遥测，探索跨 Run 自动提出候选、版本回归告警、企业身份及更细粒度的来源授权。 | 有明确业务负责人和足够已核验样本，能评估候选质量、误报和人工纠正成本；验证撤权与跨工作空间隔离。自动产生候选不等于自动发布。 |

长期投入沿这条链路展开：先把**可靠的数据和知识**交给 Agent，再让**经过核验的经验**在团队内安全复用，最后验证复用能否改善更多任务。新增宿主、度量和自动化应服务这条链路，不为功能清单提前建设。

## 边界与待决事项

- Origence 管理数据资产、上下文、Skill 和运行证据，不替代 Agent 宿主做推理、任务编排或业务工具执行。批准发布 Skill 不授予操作权限。
- 沿用 [SQLite 权威数据、AnySeek 检索、Blob 原始文件](design/agent-data-foundation.md) 的分工，不在此路线图另起检索或数据库内核。现阶段以新建数据库为目标，同版本恢复仍要验证。
- 托管部署、生产成本阈值、ContextBase 互通与 Agent one 接入按需求另立决策，不视为已承诺的交付项。
