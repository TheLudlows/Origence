# Origence 参榜准备与后续方向

更新及规则核对日期：2026-10-10。目标平台为 Agent Memory Leaderboard（AML），本期参考第二届 Agent Memory Challenge。本文记录专项计划及实现进度；勾选项的范围以对应验证证据为准，不代表正式评测或部署已交付。

建议先以文本记忆赛道建立可复现基线：完成 Add/Search 协议、样本隔离、持久化与可检索保证，再改进长对话、时间信息和证据排序。首轮以完整通过评测并获得可信基线为目标，不预设排名。

当前能力以 [STATUS](STATUS.md)、[API](API.md) 和代码为准；工程约束沿用 [AGENTS.md](../AGENTS.md) 与[平台设计](superpowers/specs/2026-09-22-memory-knowledge-platform-design.md)。本文与 [S2–S4 路线图](superpowers/plans/2026-10-09-next-stage-roadmap.md)互补：参榜不以完整经验学习闭环为前置条件，参榜结果也不能替代产品验收。

## 参赛范围与规则基线

优先准备文本赛道。代码轨迹检索与图像证据处理分别需要独立实验，放在文本基线稳定之后评估。组别和模型尚待确定，不能仅因项目开源就默认现有模型满足参赛条件。

官网 FAQ 对学术榜指定 `text-embedding-v4` 和 `gpt-4o-mini`，reranker 不限；其他模型可考虑工业榜，非商业项目也可参加。官网同时使用“开源方法榜/商业产品榜”名称，申请前确认所选组别与模型限制的对应关系。第二期材料截止为 2026-10-31 23:59、评测停止为 2026-11-04 23:59，均为 UTC+8；同赛道第二次 Full 需距首次完成满 30 天。[赛事及 FAQ](https://agentmemoryleaderboard.ai/competition/)

自托管 Add/Search，经 Smoke、Full 和复核后上榜。Add 收到消息与 request/user/session 标识，成功须持久化并可立即检索；Search 按 user_id 隔离，返回有序 `data` 证据，数量不超过 `top_k`，正式值为 100。回答与评分由平台执行。评测输入只用于本次运行，不训练、分析或分享，运行结束后 30 天内删除。[接入及数据规则](https://agentmemoryleaderboard.ai/docs)

以下实现及验收方案是 Origence 的工程选择。执行前重新核对当期协议，尤其是组别模型限制、异步 Add 例外、输入规模、超时、配额与保留要求；保存核对日期和版本，避免沿用过期规则。

新增 200 题尚未独立人工复核；当前结果不覆盖真实长对话、并发容量或 Agent 任务成功率，不能换算成 AML 分数。历史报告与原始工件保持不变，新实验使用独立版本和目录。

## 阶段一 完成可接入评测的版本

### A1 固定组别与模型配置

- [ ] 确认文本赛道、参赛组别及可用模型，登记待主办方确认的规则问题。
- [ ] 固定 embedding 模型、维度、抽取模型、提示词版本和是否启用摘要/图。
- [ ] 检查 [models.rs](../src/models.rs)：当前 embedding 与抽取共用 Base URL/API Key。需要不同供应商时拆分配置或采用明确的兼容网关，测试鉴权、响应、维度与错误映射。
- [ ] 使用新的评测数据目录重新发布并生成向量；不混用旧 BGE profile，不把改环境变量视为已完成索引迁移。

验收：真实参赛配置完成文本入库和查询；模型与维度可追溯；模型失败明确可见；旧 profile 不会混入结果。未启用的生成组件也要写入提交配置。

### A2 建立受控的用户隔离

用户映射、原子创建、派生权限复核及 AML HTTP vector 路径已实现，验证结果见 [VALIDATION](VALIDATION.md)。namespace 选用凭据的原生 tenant/workspace，由管理员显式启用；同 namespace 的 key 共享映射。2026-10-11 已补齐固定模型的摘要/图及 resolve 分支隔离回归；真实参赛配置仍需独立验收。

- [x] 以“评测凭据所属命名空间 + 完整 user_id”作为映射键，持久关联专用 workspace，保留平台传入值，不按冒号拆解、归一化或删去前缀。
- [x] 通过受控库 API 完成 scope 创建和授权；外部请求不能指定任意内部 workspace，不能伪造 AuthContext 绕过 key 的权限核验。
- [x] 并发首次 Add 对同一用户只能产生一个映射；未知用户 Search 不能回退到公共 workspace。
- [x] session_id 用于组织同一用户的来源；Search 应能检索该用户多个 session，不能把 session 当成唯一检索范围。
- [x] 固定模型回归验证关键词、向量、摘要、图、重复查询、幂等记录和撤销错误路径保持相同隔离边界；不声明真实模型质量或新增缓存能力。

验收：两个用户写入相同实体名及相反事实，所有检索模式均不串数据；同一用户跨 session 可以召回；重启后映射不变。现有完整 memory_identity 过滤只限定特定事实身份，不能替代整份语料的 scope 隔离。

A3/A4 的协议实现已完成，本地证据见 [VALIDATION](VALIDATION.md) 的“AML Add/Search 最小闭环”。2026-10-10 再次核对 [官方 API Guide](https://agentmemoryleaderboard.ai/api-guide)：同步 Add 成功须持久且可检索，Search 按 user_id 返回至多 top_k 条证据。实现限制见 API/OPERATIONS；本地测试使用固定响应的 embedding 服务，不代表真实模型质量、官方 Smoke 或容量达标。A2 摘要/图等分支的固定模型回归已补齐，真实参赛配置仍待验收。

### A3 保留消息原文并完成 Add

- [x] 新增 AML 请求/响应结构和 HTTP 适配，复用 [Service](../src/service.rs) 与已有 Worker，业务逻辑留在库模块。
- [x] 保存原始消息 content、role、来源顺序、可选时间戳和 session；缺失时间戳不伪造事件时间，接收时间单独记录。
- [x] 首版优先将批次转为不可变的会话来源与知识资产，分块保留消息边界和邻接关系。若组合成索引文本，同时保存其到原消息的映射，区分索引文本偏移与来源原文偏移。
- [x] 使用“命名空间 + user_id + request_id”登记逻辑写入及 payload hash。同请求关联原 job；同键不同内容拒绝；长 request_id 如需转换内部幂等键，保留完整值及稳定映射。
- [x] 一批数据涉及多个 job 时持久保存完整映射，崩溃后可继续；所有必要任务完成发布后才确认 Add 成功，不把 accepted 或部分成功当作整批成功。
- [x] 首版采用同步完成响应：HTTP 200、`success=true`，原样回传 request_id、user_id、session_id；未经审核绑定状态查询协议，不返回 202 代替完成结果。
- [x] 请求断线或等待超时后，重试继续观察原任务。持久处理仍由原 Worker 负责，不另建独立处理/重试循环；终止等待不等于取消已开始的处理。
- [x] 保留历次会话证据，不把整个用户历史反复覆盖为一个资产的当前版本。新增摘要或事实投影不能代替原消息存储。

验收：Add 后立即 Search；重复请求、请求处理中重试、响应丢失和宿主重启都不产生重复版本或漏批次。验证多语言、Unicode、消息跨块、超长输入以及 malformed payload。对不支持的输入明确失败，不悄悄只发布前半段。

### A4 输出可审计的 Search 证据

- [x] 将 query、可选 options、user_id、top_k 转为内部查询；首版接受 options 但不据此生成答案，也不将选项写入记忆。
- [x] 显式设置 `mode="vector"`；参考 [SearchInput](../src/types.rs)，不要继承 keyword 默认值。
- [x] 将 hits 映射为稳定 ID 与非空 content，按相关性返回；无结果输出空 data，返回数量遵守请求上限。
- [x] 将必要的角色、来源时间及原文片段放进证据正文，不能仅放入平台可能忽略的额外字段；内部继续保留 source/version/chunk/locator。
- [x] 检查 [retrieval.rs](../src/retrieval.rs) 的 4000 UTF-8 字节 query 限制及全部写入限制。按目标负载显式调整并记录限制；不要通过截断或删除选项伪装兼容。
- [ ] 初版优先复用 search，而非直接套用默认 2000 字节的 resolve。对证据数量、去重和上下文长度做单独实验，不把 top_k 当成必须填满的条数。

验收：ID 跨重试稳定、正文可追溯、排序可重现、数量不超限；返回的每条内容都是记忆证据。重复证据不能挤占主要上下文；模型不可用时不得无提示降级成另一套申报方法。

## 阶段二 完成可冻结提交的部署

已交付 [本地预检与演练工具](AML_DRILL.md)：固定向量及真实本地 BGE-M3 的小规模协议、发布后强退重启、停止宿主后的完整数据树恢复和临时树清理均通过；固定模型处理中强退恢复用例也通过；不能据此勾选以下公网/持续容量/生产清理验收。

### B1 专用实例与容量验证

- [ ] 使用独立评测实例、数据目录和凭据，部署公网 HTTPS，固定构建产物、配置和版本。
- [ ] 保持单宿主、单 Worker，先测吞吐再声明并发；多用户数据量增加时同时测排队时间、存储增长和恢复时间。
- [ ] 记录 Add 全流程与 Search 的 p50/p95/p99、失败率、模型调用及 token 数、内存峰值、磁盘占用；Add 计时包含抽取与索引生成，不能扣掉离线生成成本。
- [ ] 对网关、HTTP 等待、上游模型请求分别设置超时，验证限流与重试行为，避免长任务被网关提前断开后重复入队。
- [ ] 在声明负载下演练模型限流、暂时不可用、连接中断和宿主恢复，确认同一逻辑写入可继续完成。
- [ ] 分开检查进程、存储、Worker 和模型连通性；当前 `/health/ready` 不证明模型服务正常。

验收：完成覆盖预计 Full 时长的持续运行演练，并包含一轮恢复测试；请求积压、磁盘和供应商额度有明确容量边界。未完成压测前不声明生产 SLO，也不因延迟上升直接引入多 Worker。

费用预算按“embedding 输入 + 抽取/摘要调用 + 可选重排 + 主机/磁盘/带宽”分别估算，用实际请求量更新。保留重试带来的模型调用预算；发布幂等不保证供应商只计费一次。

### B2 清理与评测数据边界

- [ ] 区分自建开发集和平台送入的私有评测数据；公开实验可以保存逐题分析，私有评测输入不得进入该归档流程。
- [ ] 运行日志仅保留必要的脱敏 ID、耗时、状态和安全错误码，不记录消息正文、问题、候选内容、模型响应或密钥。
- [ ] 设计到期清理流程，覆盖 SQLite 及 WAL、LanceDB、图、Blob、模型缓存、临时文件、日志、备份与云快照，并确认模型供应商的数据保留设置。
- [ ] 优先采用专用实例整体退役方案，明确清理范围和运行停止条件；验证删除后无法通过服务、备份恢复或遗留副本重新读取评测数据。
- [ ] 用合成数据先演练并保存不含正文的清理证据；不把仓库历史评测工件或用户业务数据包含进清理目标。

验收：有可执行的清理步骤、期限、副本清单和检查结果。现有逻辑墓碑与 cleanup 完成只能证明退出服务检索，不能作为底层原文已清除的证明；涉及加密擦除或介质保证时单独写明实际边界。

### B3 冻结与提交材料

- [ ] 系统名称、版本、联系人、团队、参赛组别及拟公开信息完整。
- [ ] 仓库、固定 commit、构建/镜像摘要、许可证、原始工作引用和方法改动说明齐备。
- [ ] 固定模型/profile、提示词、分块、召回模式、组件开关、重排、阈值及部署配置；配置工件不含凭据。
- [ ] 提供 Add/Search/health 地址、鉴权方式、评测专用凭据的受控交付方式，以及容量、超时、限流和费用预算。
- [ ] 完成本地协议回归后再跑官方 Smoke；通过后记录所测版本，再启动 Full。Full 受理后保持代码、模型和配置一致。
- [ ] 保存允许保留的 Run/Job、版本和运行状态；异常按平台复核流程处理，不依据私有评测题现场改答案或更换实现。

验收：提交材料能唯一定位实际运行版本；Smoke 记录对应同一配置；Full 完整结束且通过官方审核后，才将结果标为正式榜单成绩。

## 阶段三 用独立实验决定提分投入

以下工作可在协议实现期间推进，但调参只使用独立开发数据。模型和语料变化后重建基线；留出集用于最终比较，不根据其结果补阈值或改标签。

| 实验 | 要解决的问题 | 比较与验收重点 |
| --- | --- | --- |
| 长对话与多语言 | 短中文合成文档不足以代表历史会话 | 加入英文、多语言、多个 session、长历史和近似干扰；报告原文证据覆盖 |
| 时间与更新 | 当前版本查询可能丢失旧状态 | 保存历次来源，比较时间标注和邻接补全；区分事件时间、接收时间与缺失时间 |
| 关键词召回 | 当前查询全部词项匹配压低自然问句召回 | vector 基线对比 BM25/向量融合；测试实体、编号、同义问法及疑问词 |
| 重排与去重 | 相关片段可能被近似噪声挤出 | 对同一候选集比较重排前后质量、token、延迟和费用；保留相反事实 |
| 多跳证据 | 正确答案可能需要多个片段共同支持 | 测全部必要证据的覆盖，不能只计命中任意一个文档 |
| 无答案与冲突 | 所有无答案题仍返回候选 | 在开发集校准证据门槛，联合报告误召回与可答题漏召回；不追求单一阈值指标 |
| 摘要与图 | 现有投影未证明质量收益 | 使用同一参赛模型、语料与预算独立消融；收益稳定且成本可接受才启用 |
| Streaming 增量 | 写入与检索交替时可能读到错误状态 | 固定增量回放节点，验证新内容及时出现、历史仍可查、未来输入不可见 |

所有实验记录数据来源与许可、划分、hash、模型版本、代码 SHA、参数、检索与证据指标、错误、延迟和费用。分块后同时报告片段级与来源级指标，不能拿现有“文档去重 Recall@5”直接比较 AML 的候选条数。需要下游答题实验时采用独立开发题和冻结的回答配置，结果标为本地代理指标。

质量结论至少说明：哪些能力改善、是否牺牲可答题召回、是否增加噪声或成本、是否在独立留出集成立。没有观察到增益的组件不进入冻结配置。

## 当前执行优先级（2026-10-11 用户调整）

先使用本地 Ollama BGE-M3（1024 维）完成协议模拟和有标签的检索基线，再测本地并发、长输入、恢复与清理。随后视需要用已授权聊天模型构造固定 Answer/Eval 本地代理指标。正式模型/组别、公网服务、域名及官方平台 Smoke/Full 后置，不阻塞本地研发。下表保留正式参榜的依赖关系，不作为本地实验的进入门槛。当前小规模演练每用户仅两个片段，不能代替长历史、多跳、无答案和排序质量评估。
