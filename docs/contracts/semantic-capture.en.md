# Controlled conversation extraction

**English** · [简体中文](semantic-capture.md)

The caller supplies original text and allowed targets explicitly. The model can propose changes only within that scope. The deterministic rules are in [memory identity and semantics](memory.en.md). For learning from conversation feedback, see [Improve / Learning](learning.md).

## Contract

- Available through the library API and POST /v1/captures/semantic. The caller supplies immutable original content and up to 20 allowed targets with complete identity and expected_version. Target properties must exist in the current workspace registry with complete conditions. Empty targets allow only unnormalized evidence.
- The model returns only a target index (or null), an operation, and statements with UTF-8 source byte ranges. Identity, tenant, approval, and publication fields are forbidden. Unknown fields, out-of-range values, duplicate targets, or fabricated citations fail the entire batch. Up to 20 candidates and 32 statements are allowed, with up to 64 KiB of original text.
- Extraction is a model judgment and does not verify truth. Callers supply stable target IDs and applicability conditions. Aliases are not resolved automatically. Proposals, negation, and ambiguity produce unnormalized evidence. A different single-value assertion becomes separate conflict evidence. If the model still returns update, the quote is saved as ambiguous evidence. An explicit memory write can confirm a single-value update. The separate long-term memory flow computes conclusions from evidence.
- At admission, check expected_version for all targets. A stale target rejects the request before creating a source or job. After admission, deterministic candidates check the version of the used target during semantic routing. Once the plan is saved, only memory entries selected during routing are rechecked, including the version and current visibility for a duplicate result. Unused targets and suggested_identity in unnormalized evidence are not continuously locked. A deterministic assert routed to conflict still checks the target version before routing, then publishes independent evidence. Uncertain candidates do not update the suggested identity. A version race for a genuinely determined fact supersedes the whole batch.
- Reuse the same memory routing function for duplicates without version increments, multi-value additions, and conflict retention. Record each candidate's routing result independently. Publish all nonduplicate results in one relational transaction. Any error prevents partial publication.
- The existing serial durable worker performs extraction. Model and tokenization work stays outside transactions. Persist the routing plan before embedding. Retries reuse its candidates, targets, and sources without reclassification. If the process exits after the model response but before plan commit, the model may be called again. Exactly-once provider calls are not guaranteed.
- Revalidate the current source and collection member sources on every recovery and before final commit. Reuse whole-snapshot withdrawal from memory semantics. A locator retains original references and sources. Add extraction metadata semantic-capture:v2 and the model name without replacing existing member sources.
- No additional worker, automatic scheduling, retry loop, hard cancellation guarantee, or database upgrade. Existing governance applies to failures, cancellation, revocation, restart, search, and withdrawal.

See [VALIDATION](../VALIDATION.en.md) for exact runs. A model stub verifies engineering contracts only. It does not establish real model classification quality.
