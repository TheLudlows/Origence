# 显式 Improve → Learning

**简体中文** · [English](learning.md)

## 范围和授权

本契约定义显式会话反馈闭环。面向新建数据库，复用当前配置的抽取模型、有类型的持久队列、串行 Worker 与知识发布路径。不新增自动触发、排序改权、记忆覆盖、Guidance 生命周期、供应商、迁移或后台编排器。确定性夹具验证工程行为，不证明事实真实、实际模型质量或 Agent 收益。

调用方显式提供稳定的 improve_id 和非空的适用条件。作用域来自认证和会话路由。模型不能放宽适用条件。正向反馈是有用性的证据，不证明事实。未受信任的轮次正文、反馈和模型响应不能授予权限。

## 持久化流程

1. 在同一个命令事务中校验调用方授权和不可变领域 ID，冻结有界批次，占据该会话唯一未完成的 run，并将有类型的 Improve 作业入队。使用作用域限定的单调反馈序号。墙钟时间和未绑定主体的反馈 UUID 不能充当游标。
2. Worker 核验归档轮次及所有证据依赖，最多获取八个提议，并机械校验精确支持 ID 和 UTF-8 引文。在核验调用前持久化该计划。
3. 使用同一套已配置的抽取基础设施，另行检查支持与可持续性。每条批准或拒绝都要先持久化，再创建下游资产、调用索引模型或执行原生写入。
4. 原子创建获接受的 Learning、支持引用、生成的来源事件、知识资产和普通 Ingest 作业。不能嵌套调用公开 Service 命令。恢复沿用原 ID 与计划。按精确 statement/conditions 去重，并在同一事务内复核有效的 accepted/published 登记。如果占位冲突，回滚暂存且不推进游标。在竞争结果确定后取消该未完成的 run，并提交新 improve_id。此规则不做语义去重。
5. 每个子任务遵循原发布与文件所有权规则。原子性以每个 Learning 为单位，整个 run 不共同提交。图发布结构以单个知识资产为单位。失败子任务会令 run 保持未完成。显式重试沿用该子任务的现有 job 与持久计划。
6. 只有全部已接受的子任务完成发布，且冻结批次的其他结果都已持久记录后，才推进会话游标。空计划或仅含拒绝的计划不创建虚假资产。已取消、被撤权或过期的 Worker 不能完成发布。

冻结批次最多含 32 条反馈及 128 KiB 模型输入。网络 I/O 前，每个已完整序列化的提议或核验请求也受 128 KiB 上限约束，包括适用条件及已有提议。初始输入超限时失败且不推进游标。适用条件、声明、说明、引文和输出数量也有校验限制。不可见轮次可按 ID 与序号登记为跳过，不暴露正文。

## 撤回和可见性

Learning 的支持要求整轮归档仍有效，包括每条历史引用、版本根、原始语义成员来源与完整语义快照。仅派生来源事件有效还不够。

重放提议或计划、索引前、最终发布、应用候选上限前，以及最终 search/get/resolve/graph/source 读取均执行同一依赖检查。清理解除无效 owner，但读取无需等清理才隐藏。以 Learning 为证据的轮次产生传递依赖，按固定边界遍历，遇到循环或超限就拒绝，不能截断后接受。区分原始成员来源版本和资产版本。普通知识更新与 restore 不得改写 Learning 的支持契约。

## 验收

覆盖公开 API 权限和严格字段、轮次→反馈→Improve→Learning 入索引→另一会话检索、命令和领域重放及并发 run、主体验证后的反馈 ID、相等时间戳、迟到反馈、持久阶段重开、子任务失败和重试、撤权和取消、畸形 JSON 与虚假引文、扩大适用条件、缺少依据的 helpful 回答，以及来源、成员和资产撤回，含嵌套 Learning 依赖。准确执行证据见 `docs/VALIDATION.md`。待执行或静态检查不能当作 Rust 测试通过。
