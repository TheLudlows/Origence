# 私有 Run 轨迹

**简体中文** · [English](runs.md)

Trace 是 Origence 的核心数据域。Run 是私有执行证据的存储和访问单位，见[架构规划](../design/agent-data-foundation.md)。创建和追加 Run 都使用已授权的关系事务。每个 Run 绑定服务端分配的私有会话与稳定逻辑 key。工作空间管理员不自动拥有读他人私有归档的权限。凭据轮换保留逻辑所有权，撤回凭据阻断重放、新写入和读取。

`run_id` 与 `event_id` 是持久重试标识。相同负载返回原回执，改变负载冲突。事件只追加，每个 Run 序号单调递增且最多 10,000 条。读取分页，每页最多 100 条。摘要指向精确不可变前缀，与可变化的最新 Run 不同。

Client/user/test 标签是与认证凭据身份一同记录的声明，不是服务端认证。上报包括工具调用、上下文引用、结果、反馈及显式 unknown/partial/not-collected 覆盖范围。无事件表示未知。自报成功未经独立验证。MCP 无法观测没有经过自身的客户端或工具活动。

调用方不可直接访问的上下文准备路径记录精确序列化服务端 bundle 的 SHA256、不可变引用、路由统计、警告、省略和预算。它只证明服务端准备了该 bundle，不能证明客户端接收或模型使用。追加事务和 Run 或前缀读取时再次检查来源可见性及私有会话所有权。撤回后拒绝读取，不泄露失效私有来源。空 bundle 合法并保留警告。接口不保证自动采集所有上下文请求、外部工具调用或结果。检索 I/O 前必须检查 Run 所有权。

选定 Skill 审阅可调用内部可信所有者前缀摘要辅助函数，不读取 Run 原始内容，也不接受调用方指定所有者 ID。来源保护仍生效，因此以私有会话为依据的引用可能拒绝另一审阅者，不能因审阅扩大私有访问。

显式 `skill_loaded_reported` 事件关联精确 Skill UUID、正整数版本及规范 SHA256。`artifact_reported` 关联不透明输出 UUID 和有界摘要。两者只是上报，不证明执行、不授权，也不证明引用对象存在。读取 Run 时不递归解析 Skill 包，因为 Skill 也可能引用不可变 Run 前缀。仅所有者可访问的前缀端点提供此类非递归引用所需的精确摘要。

## 检索观测

已准备上下文包括请求内有界检索轨迹，以及已校验的分析配置和 embedding 空间身份。对包含观测的精确序列化 bundle 计算摘要。成功幂等重放保留首次准备的标识和耗时，返回同一 bundle。请求摘要阻止事件 ID 被复用于其他请求，即使两次都返回空上下文。

成功事件为重试保存准备 bundle 的私有副本。重放先于模型和检索 I/O 核对事件与请求摘要，重验当前权限、所有权与全部原始引用。后端故障或语料更新仍可返回原 bundle 与回执。分页轨迹不包含此内部快照。追加事务重复检查重放条件，因此并发的首次成功优先于随后的失败。来源撤回仍阻断重放，快照不授予读取被撤回来源的权限。

在所有权与输入检查后，失败准备可以追加服务端观测事件，只包含安全错误码与不含正文的观测。失败尝试不可变，恢复后使用新事件 ID。轨迹与前缀读取保留所有所有权和来源保护。后端进展在检索后采样，不能当作结果的原子读取、Origence 事务、交付证明或独立核验证据。见 [API](../API.md#检索诊断)。查询诊断 v2 返回当前 embedding 空间 SHA256 或 null，每个响应均核对已受理的空间及分析摘要。

### 上下文查询向量化的输入用量

Origence 对已配置 embedding 端点的请求可产生一条 `retrieval.context_query_embedding`，加入既有准备检索证据，即使向量化或后续检索失败也可记录。包含 `model_config_sha256`（已配置的 embedding profile 摘要，不能证明实际模型）及 `provider_reported_prompt_tokens`（只接受端点 `usage.prompt_tokens` 中的无符号 32 位整数）。显式零值保留零。未知或不可用为 null。字段缺失表示没有观测，例如关键词模式或旧证据，不代表零。旧 bundle 序列化时省略此字段，保留现有摘要。

这是 Origence 观测到的供应商自报输入用量，不能作为独立度量、客户端 Agent 用量、Run 总量或计费。普通 Context 预览不附着到 Run。仅现有准备记录路径归档此证据，可能不包含全部物理请求，例如回执前的重复尝试。不推断定价或汇总。观测不存储查询、向量、端点 URL、模型名或凭据。

## 精确内容版本的已记录 Run 关联

`GET /v1/assets/{asset_id}/runs?version=N&after=UUID&limit=25` 在当前逻辑 key 内只读查找。必须提供正数 `version`，不隐式取最新。`limit` 范围 1–100。`after` 默认 nil，按 Run UUID 翻页，与时间戳无关。响应含 `asset_id`、`asset_version`、`items`（仅 `run_id`、`created_at_ms`）、`next_after`、`scope:"current_logical_key"` 和 `coverage:"recorded_references"`。不暴露 Run 摘要、查询、正文或引文。

查找表是投影，与已接受的客户端上下文引用和服务端准备事件原子维护。每个所有者、内容条目、版本与 Run 保存一个指针，以首条不可变归档引用为证明。重试不重复写。作用域、所有者、内容条目、版本及 Run 主键用于有界范围读取，不扫描全部 Run 或搜索 JSON。在一次授权读快照内核对精确版本、来源、逻辑所有者与私有会话、权威事件引用身份和当前引用可见性。投影不授予访问权。证明不见或缺失时保守省略，即使后续事件也引用内容条目，也不查找其他事件替换撤回证据。游标按已检查指针推进，空页也可带 `next_after`。

此接口只返回已记录的关联，不保证完整采集或证明接收、使用。响应不授予完整轨迹读取权，打开 Run 时复核该轨迹自身的来源，包括无关引用。工作空间管理员不能枚举其他逻辑 key 的关系，轮换保留所有权。撤回内容条目或来源拒绝查找。UI 重试清除旧结果，显示空结果和错误状态，并在 403/404 时清除显示内容条目。

新建库 schema 增加 `oc_run_asset_refs`。精确准入拒绝缺表的现有库，不创建表或改写证据。同 schema 重开保留关联，不执行迁移或回填。

## Run 创建总览

`GET /v1/runs` 和 `GET /v1/runs/overview?window=24h|7d` 按所选工作区的有效角色授权。管理员可列出并统计工作区全部 Run，其他角色查看自己的 Run。列表显示 Run ID、所属逻辑 key、创建时间和最新的上报结果。缺少结果或上报未知时显示未知。摘要和详细链路只向所有者开放。每条持久 Run 记录只计一次，轮换保持逻辑所有者。空范围返回零值，无需创建会话。

滚动窗口结束时刻取一次服务时钟。区间为 UTC Unix 毫秒 `[end_ms - duration_ms, end_ms)`。各桶从窗口起点起连续左闭右开，`24h` 每桶一小时，`7d` 每桶 24 小时。它们以精确请求截止时刻为锚点，可跨整点或 UTC 午夜。服务在同一已授权 SQLite 读快照中计算全部桶，包括空桶，并以 `created_runs` 返回总和。

创建计数来自持久 Run 记录，与结果、事件数和历史证据是否仍可读无关。重复提交同一已受理 Run ID 不增加计数。既有按 UUID 排序的 Run 目录分页不变。成功任务、核验结果、端到端延迟、Token 和费用须另行观测。

既有主键按 Run UUID 排序。覆盖索引 `oc_runs_owner_created_at` 支持有界的所有者和时间范围计数。个人请求最多执行 24 次互不重叠的索引区间计数，覆盖不超过七天。管理员请求在所选工作区内扫描一次覆盖索引并分桶。工作量随扫描项增长，两种查询均只读索引。数据库结构准入要求此索引。

### 整轮计量

执行方取得整轮数据后，用 `POST /v1/runs/{run}/events` 或 MCP `context_run_report` 上报。仍须拥有 Run 和写权限。

```json
{
  "event_id": "67ba4d8c-8dd0-4f93-a784-085f4e095d27",
  "reporter": "client",
  "observed_at_ms": 1795651200000,
  "event": {
    "kind": "metering_reported",
    "duration_ms": 1820,
    "agent_tokens": 1246,
    "estimated_cost": {"currency": "USD", "micros": 2300}
  }
}
```

- `duration_ms` 是执行方用单调时钟测得的任务起点至最终返回时长。`agent_tokens` 是执行方从完整模型用量记录取得的整轮输入和输出总量。两者均为无符号 32 位整数。模型未提供完整用量时省略，Origence 的查询向量输入 Token 不加入这个总数。
- `estimated_cost` 与 `billed_cost` 分别接收执行方提供的费用估算和能归属到这个 Run 的账单金额。两者都使用三字母大写币种和非负整数微单位（每单位一百万微单位），单次不超过 `9007199254740991`。Origence 不查询账单或自行换算。事件保留认证凭据、报告方和观察时间，以便追溯。
- 每次至少提供一项。每个 Run 的每项只接受一次，同事件 ID 和同载荷重试返回原回执。可以用新事件补齐原先缺失的项，例如账单晚到。新事件重复上报任何已存在项时，整笔拒绝并返回 409。明确上报的零值保留。
- `GET /v1/runs/overview` 的 `metering` 汇总该窗口内**创建**的 Run，包含当前已收到的计量。`duration_p95_ms` 采用已上报耗时的最近秩 P95，`duration_runs` 为样本数。`agent_tokens` 为已上报 Token 总数，`token_runs` 为样本数。无样本时数值为 null。费用按 `basis`（`estimated` 或 `billed`）和 `currency` 分组，每组返回 `micros` 和 `runs`。Token 和费用总量用十进制字符串精确返回。不同币种、估算与账单不相加。

计量来源为调用方显式上报。现有 Codex/Claude Code Hook 没有完整计量数据，插件不会自动生成这类事件。管理员在工作区总览只读聚合，Run 原始事件仍由所属逻辑 Key 私有读取。计量投影同事件一起写入并按创建时间和权限范围索引，查询不扫描 Run 正文。SQLite 只在新库安装该结构，旧库按既有准入规则拒绝打开。

## 外部核验记录

所有者转录的外部核验遵循独立[核验契约](run-verification.zh-CN.md)，绑定精确 Run 前缀并保留归因、依据、未知使用版本和撤回信息。这不是平台认证，声称的核验人或 `reporter=user/test` 标签不授予私有 Run 读取权。

## 私有 Run 的 PDF 页预览

`GET /v1/runs/{run}/pdf-source?sequence=N&evidence_ref_id=UUID` 解析该 Run 事件中已归档的 PDF 引用。UUID 由服务端分配，从归档引用读取。查询不接受调用方提供的文件 ID、内容条目版本、页码、区间或解析器。要求既有原始来源 Write 权限及当前逻辑 Run 所有权。文件读取和解析前后核对事件引用可见性、精确发布成员与根来源和原始文件。

响应包括 `asset_version`、已知且从一开始的 `page` 或 null，以及包含 `before`、`highlight` 和 `after` 的 `span` 或 null。区间要求校验原始文件完整性、归档 PDF 解析器标记、有效页内 UTF-8 字节范围、不可变已发布块的哈希及提取页内唯一精确匹配。出现提取警告，或正文有歧义、无效或不可用时，span 为 null。返回的是该页已核验的提取文本。PDF 查看器使用另行读取的原件并定位记录页，无坐标覆盖或 OCR。纯扫描文件仍按既有入库规则。

添加 `original=true` 将以禁止缓存的附件返回同一已授权并校验完整性的原件。UI 每次打开都重新获取，用浏览器 Blob URL 附加页码片段。撤回来源和凭据使新的预览与打开被拒。用户已接收的副本或已打开预览遵循原下载语义。

预览沿用上传大小、页数和提取文本上限。解析在异步线程和存储事务之外进行。每进程最多两个阻塞预览任务并发，Busy 可重试。取消 HTTP 请求不会中止正在运行的解析器，解析结束才释放准入许可。入库解析器标记、持久 Worker 与新库 schema 保持不变。
