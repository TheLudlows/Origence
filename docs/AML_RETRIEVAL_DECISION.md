# AML 检索与回答可靠性：调研及阶段决策

日期：2026-10-11。基线：Origence main de17218125cccd83e6cce3b5c39340fc5ae3bd52。状态：下一轮实验方向已确定，模型胜出者与生产接入尚未确定。本次只有文档调研、代码核对和方案取舍，没有新增模型评测结果。

后续执行证据见[诊断与专用重排回归](../evals/aml/diagnosis/README.md)；本文保留研究时的取舍依据，当前进度以 STATUS 为准。

## 1. 决策

采用“受权限约束的原文召回 → 可替换重排 → 按预算组织原文证据”的检索主线。优先增加专用多语言 cross-encoder 与现有聊天模型重排的同候选集对照；证据充分性与答案核验作为独立实验变量，不预设核验器必须进入线上链路。正式 AML Search 继续返回原文证据，由平台负责 Answer/Eval。

这修正了上一轮“先加证据核验，再接入 Search”的笼统建议：检索排序、证据是否足够、答案是否被证据支持是三个不同问题。不能用同一个相关性分数或一次额外模型调用代替全部判断。当前不以更复杂的图、全量查询扩展或自研通用事实类型系统作为前置。

依据来自三部分：既有设计约束、Origence 本地失败记录、以下一手资料。业界实现证明某种机制可用，不证明它在本机、本语料或 AML 上更优。

## 4. AML 边界与现有代理的差异

[AML 官方说明](https://github.com/AML-memory/agent-memory-leaderboard)明确参与者提供 Add/Search，平台控制 Answer、Eval 与编排。复核固定提交 1b8142bfe0f20f1c5218d6b554aa0012de34e504 的 [LongMemEval pipeline](https://github.com/AML-memory/agent-memory-leaderboard/blob/1b8142bfe0f20f1c5218d6b554aa0012de34e504/data/longmemeval-s/pipeline.py) 与 [BEAM pipeline](https://github.com/AML-memory/agent-memory-leaderboard/blob/1b8142bfe0f20f1c5218d6b554aa0012de34e504/data/beam/pipeline.py)，可以检查公开回答模板与评分流程，但仓库不包含完整平台编排或私有题库。

因此 Search 中不生成最终答案，不把模型判断出的“无法回答”伪装成原始记忆，也不因最终一跳缺失就丢弃所有有用的桥接证据。无答案题返回候选仅是检索观察，不等于最终错误作答。接口数量上限与实际上下文预算分别处理；本地固定最多 5 条是实验选择，不是通用平台要求。

现有 tools/aml_answer.py 要求引用且采用短语匹配代理；公开 LongMemEval 模板允许由原始观察推导答案，并不要求答案逐字出现在原文。因此未来核验要支持由完整证据链成立的推论，不能退化成字面字符串匹配。公开 pipeline 可在本地用于公开/自建数据的合同对齐实验；模型、数据、编排不相同时仍不是官方 Smoke/Full。

## 5. 本地证据支持什么、不支持什么

新主题只重排将 Recall@5 从 63.54% 提升到 95.83%，Answer 代理从 9/16 提升到 15/16；扩展重排的 Answer 代理同为 15/16。两者检索 p95 分别约 1.55 秒和 3.91 秒。这支持优先研究较简单的重排，不证明它已经具备可靠语义判断。

开发集仍出现工单号代替序列号、相似活动温度串用，无答案正确拒答由 vector 的 3/3 降至重排的 2/3。另有多跳证据在 top-100 外，以及已召回后被 top-40 候选裁剪挡住的情况。需要分开记录：

1. 召回缺失：原候选池没有必要来源。
2. 预算/排序损失：候选池有，但筛选或打包后缺失。
3. 阅读/推理错误：完整来源已提供，回答仍混淆对象、属性、时间或数值条件。
4. 拒答错误：没有足够证据仍回答，或有足够证据却拒答。
5. 运行错误：模型超时、格式错误、预算超限；不算正确拒答。

聊天模型的集合式重排可能保留多条桥接关系，但已有格式和超时成本；专用逐对评分减少生成结构问题，却也可能给间接桥接事实低分。两者必须同候选、同证据预算对照。不能提前指定任何一个胜出。

## 6. 下一轮具体方案

### 6.1 先诊断，再冻结比较

沿用已有原始候选与回答，标注上面的失败阶段。加入正确证据输入的诊断臂，只估计阅读器在证据充分时的表现；金标准证据只进入明确标记的离线诊断，不进入可部署检索器、路由器或核验器。

新增成对反例覆盖：相似主体、属性替换、旧新计划、事件时间与入库时间错序、否定与条件、数值单位/严格边界、缺一跳、多语言与消息内注入。每种反例都配可答正例，避免以全面拒答获得表面改善。按完整用户/会话/主题切分；在模型调用前冻结数据、标签、预算、提示词与判定规则。自建数据若仍由同一 agent 编写，明确不具有独立人工复核。

公开来源验证优先采用 LongMemEval 的固定清洗版子集，先登记版本/许可、抽样规则和不可调参的测试划分；其结果单列。公开题不等于隐藏测试题，也不代替 AML 私有评测。独立人工复核未完成时保留限制，不阻塞离线诊断但不宣称生产验收完成。

### 6.2 检索对照的最小矩阵

| 实验臂 | 内容 | 目的 |
| --- | --- | --- |
| R0 | 当前原文 vector | 固定基线 |
| R1 | 相同候选 + 现有聊天模型重排 | 保留已观察到的收益对照 |
| R2 | 相同候选 + bge-reranker-v2-m3 | 测本地专用重排质量、资源和延迟 |
| R3，按诊断触发 | 胜出重排 + 有界邻接或缺失关系补查 | 仅处理候选缺失/桥接丢失，单独消融 |

开发阶段分别检查候选深度 40/100 与最终证据数 5/10/20，并在同一阅读器 token 预算下比较；完整网格仅在预算内进行，最终测试前冻结单一主配置。候选数不能突破每请求字节、模型输入及总调用限额，预算不足须可见失败或使用预先冻结的明确截取规则；不得悄悄截断历史消息。更长上下文的收益单列，不能算成 reranker 自身收益。

R2 先检查本机 CPU/GPU、内存和模型运行依赖。Ollama 中已有 bge-m3 embedding 不代表 reranker 可用；不得在报告中把未测的本地推理当作免费或必然更快。先复用成熟库做实验，不为此在 Rust 核心增加 Python 子进程或模型服务。

不默认启用 HyDE、多轮 agent 检索、摘要/图重建或全量查询扩展。只有 R0–R2 明确显示候选覆盖成为主要瓶颈时才进入 R3；补查只使用问题和实际证据，不使用 gold、题型标签或参考答案。

### 6.3 回答可靠性作为独立轴

固定主 Answer 配置，对选定检索输出比较：A0 原 Answer、A1 增加证据充分性门控、A2 生成后逐主张核验。先分别消融 A1/A2，再决定是否组合，避免一次增加多个组件无法归因。

核验检查问题要求的主体、属性、时间/条件、值和完整桥接链；每个判断关联原始来源。状态至少区分 supported、contradicted、insufficient 和运行 error。精确引用、ID 和字节范围可确定性检查；语义支持仍是模型判断，需要独立标签校准。不得把高相似度、合法引用或模型自报置信度直接当正确概率。

同一聊天模型同时充当回答者和核验者不能视为独立复核。初期只能称为同模型消融；结合成对反例、固定 rubric、独立人工审阅，条件允许时增加不同裁判模型。核验器本身的错误放行和错误拦截都要计量。供应商未给出的真实概率不自行补造。

A1/A2 仅用于本地产品回答研究；另设固定公开 Answer 合同的检索比较，不能把修改自有 Answer 后的成绩归为 AML Search 提升。

## 7. 决定接入的依据

报告候选池 Recall、预算内完整证据覆盖、各类错误作答、可答题拒答、引用支持，以及 answered/assigned 的回答覆盖、correct/answered 的选择性准确率和 correct/assigned 的端到端成功率。运行错误保留在全部被分配问题的分母中；不通过丢弃错误或全面拒答抬高结果。

同时记录冷/热状态、固定并发下的 p50/p95、超时率、输入/输出 token、模型调用、峰值内存和本地运行条件。对每条问题做配对比较，按会话等独立单位统计区间，重复推理轮次不增加独立样本数。模型与裁判不确定性分别披露。

进入可选生产接入之前：来源/权限/版本/原文字节约束通过；冻结测试上的完整证据与正确作答没有被无依据牺牲；错误回答的改善未仅来自覆盖率下降；已知高风险反例和可答正例同时通过；延迟/资源预算在测试前确定并满足。小样本或宽区间只能支持继续实验，不能宣称普遍有效；业务容忍度、阈值和非劣界限须在验证阶段定义，不能看测试结果后补定。

如果接入失败或模型不可用：本地实验明确记录运行错误。未来产品可讨论显式降级，但 AML 的申报配置不得无提示切回另一方法。具体超时、回退、预算和错误契约须另行设计与测试；本次不修改 API、写入 Worker、取消、隔离或来源保证。

## 8. 执行顺序与本次完成范围

下一步按“失败归因/正确证据对照 → 新反例及公开数据划分冻结 → 专用与聊天重排比较 → 充分性/核验独立消融 → 可选接入评审”执行。服务、域名及官方 Smoke 继续后置。

本次完成仓库调研复核、一手资料核对、方案决策和状态更新；没有下载新模型、调用付费模型、运行新的质量实验或改变正式 Search。未解决事项是专用 reranker 的本机表现、核验器净收益、独立人工复核与真实长历史上的效果。历史实验工件保持不变。
