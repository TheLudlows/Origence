# Origence 演进取舍与现有规划对比

## Nowledge Mem × TrueMemory 融合评审稿

**版本：v2.0｜日期：2026-10-10｜状态：建议稿，未变更仓库计划或实现**

**结论：保留现有 S1–S4 主线，不再开一条“复刻竞品”的平行路线。** 两款产品最有价值的启发，是把已有记忆与知识能力接入真实工作流程；对 Origence，应优先补充可靠会话输入、可追溯工作上下文和生命周期诊断，而不是重建存储、版本或混合检索。

### 本版给出的明确取舍

| 结论 | 对应内容 | 如何执行 |
| --- | --- | --- |
| **借鉴并补充** | 一个真实宿主连接器；消息级可靠归档；工作快照与启动预览；逐阶段诊断 | 纳入 S3、S4；检索诊断从 S1 开始。补充到已有模块，不另建底座 |
| **已有规划，完善即可** | 语义冲突、单值/多值、会话反馈、Improve/Learning、EvidenceBundle、摘要/图消融 | 保持原计划；增加契约、反例和验收，不重复立项 |
| **实验后再决定** | Reranker、查询扩展、加工筛选、基础索引与智能加工的运行时拆分 | 先记录瓶颈；只把通过同预算对照的方案纳入默认路径 |
| **暂缓** | 自动 Crystal/Wiki、Skill 编译分发、通用路径导航、跨产品导出格式 | 不进入 S1–S4 必交范围；出现明确使用需求和收益证据后再评审 |
| **不采纳** | 相似度授权覆盖、热度等同可信度、筛选器删除唯一原文、全量后台自主整理、再次替换存储 | 与治理原则冲突，或当前没有足够收益支撑；不是“以后自动补上”的待办 |

### 与 v1.0 的关键变化

不再把 11 个借鉴方向统一当成新增功能。保留 E01–E11 编号，但将每项拆成“已有实现、原有规划、真实增量、最终判断”。尤其拆开 **Learning 与 Crystal、评测开关与发布契约、备份恢复与可移植导出**，防止捆绑后错误扩大或推迟范围。

**阅读路径：** 第 1–2 节看现有规划；第 3–5 节看逐项对比；第 6–9 节看取舍理由；第 10–12 节看实施与验收；第 13–14 节看文档修订和来源。

### 1.2 Origence 原来打算做什么

整体设计将产品定位为 Rust 实现、可本地部署的团队 Agent 记忆与知识平台；原生 tenant/workspace 隔离不是等 SaaS 阶段才加入。产品对象包括 Source、Artifact、Memory、SessionTurn、Guidance 和 Learning，各自具有不同生命周期。[O6]（§1–2）

| 产品阶段 | 原有规划 | 对本次借鉴的约束 |
| --- | --- | --- |
| **P0：知识可用且可治理** | 本地存储闭环、知识入库、混合检索、自动发布、来源与撤回、任务与隔离 | 优先证明检索与治理正确，不以新界面掩盖基础质量问题 |
| **P1：会话到长期记忆** | 会话问答、指导、反馈、经验蒸馏、水位及阶段化 Improve | 会话捕获与工作上下文应接入这条已有主线 |
| **P2：增强与服务化** | GraphCompletion、业务有效时间、企业身份、文档 ACL、配额计费、生产后端等 | 保留为需求驱动；不因竞品有此能力而全部提前 |

原设计明确不做 Agent 编排/工具执行、通用模型代理、互联网爬虫和无来源经验黑箱；首版不做 Skill 资产。本文沿用这些产品边界。[O6]（§1.2、§10–11）

### 1.3 当前已有，不要重复建设

已具备 SQLite 关系库与队列、LanceDB、SQLite 图、本地 Blob，单宿主和单 Worker；已有 HTTP、只读 MCP、身份绑定、版本、来源、撤回、幂等和发布账本。已有 keyword/vector/hybrid、RRF、摘要/一跳图证据与带引用的字节预算。完整会话主闭环、语义冲突及类型化上下文仍未交付，应用层完整后端解耦也未完成。[O1] [O2] [O3]

### 2.1 不能因“借鉴”而变成新增项目的能力

# 3. 逐项对比：接入、工作记忆与语义

以下五种判断贯穿全文：**补充借鉴 / 既有完善 / 实验决定 / 暂缓 / 不采纳**。补充借鉴不等于立刻全部开发；实施时机仍服从阶段依赖。N 为 Nowledge Mem，T 为 TrueMemory。

| 项目 | 竞品可参考的机制 | Origence 已实现 | Origence 原有规划 | 融合后的取舍与增量 |
| --- | --- | --- | --- | --- |
| **E01 连接器能力** | N 区分 transcript 与 handoff；T 按 hooks、启动事件声明能力。[N2] [T2] | HTTP；MCP 为 search/resolve/get 只读工具。[O2] [O3] | 有 Agent/SDK/MCP/CLI 接入目标，未细化宿主采集与兼容矩阵。[O6] | **补充借鉴，S3。** 增加一个真实适配器、能力自检和恢复；不要先铺开所有客户端 |
| **E02 原始会话** | N 保存 Threads 再提炼；T 当前入库路径先抽事实，不能证明完整会话已归档。[N2] [T3] | 来源事件可读取；capture 是文本抽取，不是会话消息协议。[O2] | SessionTurn 保存问答、证据、反馈和轨迹。[O5] [O6] | **既有完善 + 协议增量，S3。** 细化消息 ID、修订、分支、水位、保留期；原文先持久化再加工 |
| **E03 工作记忆** | N 提供启动 Context/Working Memory；T 通用启动召回按预设主题组装。[N1] [N3] [T4] | resolve 可按查询组装带引用内容；没有完整工作快照。[O1] [O2] | S4 已规划统一证据、分路和任务预算。[O5] | **补充借鉴，S4。** 将任务目标、决策、已证实进度与待办做成可重建投影；不新建权威事实库 |
| **E04 语义演化** | N 区分替代/补充/支持/挑战；T 保护纠正和数字差异。[N3] [T5] | 稳定身份、版本前置条件、原文引用；不等于语义正确。[O1] [O2] | S2 已规划单值/多值、歧义、否定、冲突；身份规格已规划证据关系。[O4] [O5] | **既有完善，S2。** 补关系与断言状态、反例和策略一致性；无须照搬全部记忆类别或另造版本系统 |

### 对比结论

**E01 的宿主集成和 E03 的启动工作快照，是产品接口层较明确的新增范围。** E02 则是把原有 SessionTurn 从“保存一轮问答”推进到“可可靠同步、恢复和追溯的事件协议”。E04 主要是把已写明的语义安全原则变成实现和测试，不应再建平行的 Memory Evolution 子系统。

**不必要的附带范围：** 为会话捕获强制代理所有模型请求；让 MCP 自动获得整段对话；为展示工作摘要建设独立项目管理器；为语义演化要求每个短事实都建图。它们均不是本阶段的必要条件。

### 对比结论

**不是每项都需要“再加一层”。** E05 的候选融合已有；E06 的证据与任务关联已有基础；E07 的评测开关已有任务；E08 的 Learning 已是 P1 核心。新增工作应落在可验证的差量上，而不是重复起名。

### Encoding Gate 的独立取舍

T 的门控采用新颖性、重要性和变化信号，并输出决策原因；这些启发式有参考价值，但其固定权重不能证明适合中文技术知识。[T8]

**观察性打标可以试；硬性门控不是 S2/S3 前置。** 首版可以只减少无意义加工，不删除已获准保留的唯一原文，也不阻断用户明确授权的保存请求。是否将门控纳入默认提炼路径，必须通过“保留原文/开启门控”的端到端对照。

### 5.1 v1.0 中三个容易扩大范围的组合，予以拆开

| 原组合 | 现在保留的内容 | 不随之自动启动的内容 |
| --- | --- | --- |
| 跨来源综合与 Learning | S3 的有条件经验、来源链、显式 Improve、复用验证 | 自动主题发现、长文章重写、Wiki 更新与浏览界面 |

### 5.2 判定“暂缓”是否应转为实施

暂缓不是默认承诺。每项都需要提出真实使用场景、证明现有 API 无法合理满足、给出范围与费用上限，并验证不破坏来源和权限。没有这些条件，继续保留在设计备查中，不占用 S1–S4 完成标准。

Skill 尤其不能仅凭少量同源测试就认定可靠。单独恢复旧快照无法知道备份后发生的撤回；需要可信的后续墓碑/撤回记录，缺失时只能隔离恢复并明确限制，不能宣称自动保持了后续删除状态。旧摘要和旧 Skill 使用时也须验证支持来源。

# 6. 应借鉴的第一条主线：可靠会话输入

**决定：在现有 Session 设计中补消息级协议与一个真实宿主连接器。** 参考的是 N 的原文与提炼分离、T 的适配器能力边界；不是照搬多进程直接写库或所有宿主共用同一承诺。[N2] [T2] [T3] [T4]

### 6.1 处理路径与职责

宿主真实消息 → 客户端解析与脱敏 → 本地待发送队列 → Origence HTTP/Service → 原始事件持久化确认 → 独立索引与提炼 → 既有发布及来源治理。

连接器不需要模型来“重述聊天”；模型不可用时，授权消息仍应可归档。对只有交接摘要的宿主，明确标为 handoff，不补造缺失消息。MCP 继续承担工具调用，生命周期采集由真实宿主能力承担。

| 必须补充的契约 | 建议做法 | 明确排除 |
| --- | --- | --- |
| 消息身份 | scope + connector instance + external session + message/revision；保留分支或父消息 | 只按正文 hash 去重，把两次“继续”合成一条 |
| 可靠传输 | 至少一次传输；幂等接收；确认后推进连续水位；尾部不完整延后重读 | 只在正常退出时保存；发送即当成功；宣称网络恰好一次 |
| 内容与保留 | 记录角色、原文范围、采集类型、截断/脱敏标记；设置容量与保留期限 | 隐藏推理、密钥、认证头以及无限保留全部工具正文 |
| 状态与治理 | 持久化、索引、提炼、发布分别可见；原文权限与普通检索权限分开 | 抽取失败就丢原文；reader 因摘要引用而获得敏感会话访问权 |

### 6.2 与既有 SessionTurn 的关系

建议以消息事件保存原始记录，SessionTurn 作为问答及证据关系的聚合视图。这样既兼容原来的会话—反馈—Improve 方向，也能处理回复重生成、编辑和分支。具体 DDL、URL 与修订语义在 S3 规格中冻结；不把现有 `/v1/captures` 偷换为会话存储接口。[O2] [O5] [O6]（§4、§7）

工具输出是否保存，以授权和需求决定。客户端与服务端同时记录采集策略版本；先脱敏再进入可能外发的模型管线。客户端待发送队列同样包含敏感数据，需要权限、清理和可见告警。

### 6.3 本切片的完成条件

在一个真实宿主上回放包含纠正、工具失败、回复中断、重复 hook、日志轮转与服务不可达的会话。逐条比对“应采集清单”和服务端消息身份；重放不得制造重复事件；原文可按权限定位。之后再接入显式 Improve，不以“已保存几个抽取事实”替代会话可靠性验收。

# 7. 应借鉴的第二条主线：语义安全与工作连续性

### 7.1 语义演化：补规则，不重建记忆模型

**决定：沿 S2 完善已有身份与冲突契约。** 重点是防止错误覆盖和条件丢失，不是复制竞品的全部类别名称。事实/提议/计划/决策等差异，可用业务类别与断言状态表达，但不需要为每个类别建立独立存储系统。[O4] [O5]

建议顺序为：认证与来源校验 → 稳定主体、属性和条件定位 → 单值/多值与断言状态 → 判定重复、替代、补充或冲突 → expected_version 与发布条件复核。相似度提供候选，不能决定可覆盖的身份。[O4]

| 输入变化 | 需要保留的语义 | 处理边界 |
| --- | --- | --- |
| “30 秒”改为“3 秒” | 数值变化，不是重复 | 保留精确原文，按相同身份与条件判定更新 |
| “生产启用”改为“生产禁用” | 否定与纠正 | 筛选和去重不能因高相似而吞掉更新 |
| “考虑使用 B” | 提议，不是已生效决策 | 不能覆盖当前配置或状态 |
| “测试使用 A / 生产使用 B” | 适用条件不同 | 不合并成无条件的全局规则 |
| 多份材料复述同一消息 | 同源传播，不是独立证实 | 支持关系去重，避免循环自证 |

### 7.2 工作记忆：在 S4 增加一个上下文投影

N 的 Context 展示某次 AI 运行获得什么信息，并在可支持的连接器上提供启动包。Origence 可借鉴这一使用方式，但不需要复制个人 Profile/规则编辑的全部界面。[N1]

建议工作快照包含：**任务目标、已确认决策、经证据支持的进度、未解决问题、下一步、精确引用**。项目与任务标识从明确输入或受控映射取得，不能仅凭客户端名称和目录文本就决定授权范围。

**按需构建优先。** 首版在开始/恢复任务或显式刷新时构建；必要时由已有 Worker 生成可缓存摘要。没有规模证据前，不先建独立的每日常驻知识 Agent、定时整理服务或复杂增量依赖引擎。

快照需区分“用户要求”“用户决定”“助手声称完成”“工具观察”“验收确认”。源版本、授权或任务输入改变后，应失效并重建；读取时仍校验授权和来源。TTL 只管理陈旧时间，不能替代撤回核验。工作快照也不替代遇到具体问题时的 search/resolve。

**验收：** 同一任务跨会话恢复时，能继续正确步骤、减少重复说明；不能把未验收的助手报告当成完成，也不能把旧项目内容带到另一个 workspace。

# 8. 应借鉴的第三条主线：诊断先行，优化有据

### 8.1 统一分数和阶段状态

T 的去重代码区分余弦相似度与降级/融合分数，并保护纠正与数字差异；N 展示检索策略及评分组成。Origence 应借鉴契约和观测点，而不是用一个综合“置信度”承担排序、去重和真假判断。[T5] [N5]

在现有 SearchHit/EvidenceBundle 方向上补充：分路、原始排名、score_kind、模型/策略版本、验证结果、纳入或省略原因。以 request/session/job/asset/source 关联现有记录；默认只记必要元数据，敏感正文受独立授权和保留期控制。[O2] [O6]（§6.3）

| 证据记录 | 准确含义 | 不能据此声称 |
| --- | --- | --- |
| retrieved | 检索返回过的有效候选 | 模型已经读到 |
| provided | 已放入实际请求的上下文 | 模型确实依赖了每一条 |
| cited | 输出显式引用了某项 | 引用一定支持该结论 |
| support_check | 经额外核验的引用支持结论，带核验方法 | 自动获得永远真实的标签 |

原路线图的“实际使用证据”建议改为上述可观测定义，并保留回答与反馈关联；不要记录或推测模型隐藏推理。[O5]（S3）

### 8.2 优化次序由失败位置决定

**候选缺失**：检查查询解析、中文词项策略、向量配置和前置范围。**候选存在但排序低**：试 reranker。**排序正确但未进入上下文**：修预算、片段范围和去重。**正确证据已提供但答错**：检查生成与引用，不继续盲加检索分路。

依次比较 keyword/vector/hybrid、独立摘要/图消融、重排，最后才试 HyDE 或多查询。固定语料、标注、模型和最终上下文预算，记录调用费用、耗时及未回答问题；调参开发集与最终留出集分离。[O5] [T6] [T7] [T11]

### 8.3 不把实验开关偷换成运行时部分发布

E07 首先只完成原计划的独立评测开关。只有数据表明摘要/图加工显著拖延基础检索，或故障确实阻塞主要需求，才设计独立 enrichment 任务与分步就绪状态。启用新契约前，维持现有“所选加工步骤失败则任务失败”的语义，不能吞错误取得成功状态。[O2] [O5]

调用外部 reranker 可能外发候选正文；查询扩展也会外发查询。两者需分别授权并设置预算。扩展产生的假想文本只能用于查询，不能写成事实或当作答案证据。

# 9. 哪些没必要，哪些只是暂缓

**“没必要”有两种情况：已有能力不应重做，以及机制不适合 Origence。它不同于“当前做不完”。** 下面的拒绝项不自动进入后续路线图。

| 项目 | 判断 | 理由与替代做法 |
| --- | --- | --- |
| 再造 Hybrid、RRF、通用任务器、版本系统 | **不重复建设** | 基础已有；在现有路径补契约与实验即可。[O1] [O2] |
| 为单 SQLite 形态再次替换 LanceDB/图层 | **不采纳** | 没有当前瓶颈与对照数据支撑；会中断检索质量与会话主线 |
| 相似度高就覆盖/去重 | **不采纳** | 数字、否定、条件及主体变化可能很相似；用稳定身份与语义规则 |
| 热度、反复出现等于事实更可信 | **不采纳** | 错误也会自我强化；相关性、访问统计与证据支持分开。[N5] |
| 门控低分即删除唯一原文 | **不采纳** | 未来问题不可预知；门控先只影响加工，不取代保留/删除策略 |
| 默认把新聊天提炼为高优先级指令 | **不采纳** | 外部内容和 Guidance 不应获得系统指令权；复用宿主授权。[O4] |
| 完整仿生层、固定衰减/权重照搬 | **不采纳固定配方** | 缺少中文技术语料实证；只保留可测量的独立候选机制 |
| 桌面客户端、复杂图可视化、个人档案全套 | **当前无必要** | 不直接证明平台 API 和 Agent 效果；先用 API/CLI 完成闭环 |
| 通用模型代理、自主工具执行/研究 Agent | **不纳入本轮** | 原产品边界已排除；采集、加工和检索不要求掌控 Agent 执行。[O6] |

### 后置事项的触发条件

| 暂缓项 | 何时值得重新评审 |
| --- | --- |
| Crystal / 自动 Wiki | 多来源综合问题高频出现，现有 resolve 明显重复耗费预算，且有可维护的来源依赖 |
| Skill 编译与分发 | Learning 在独立任务集显示持续收益，并有真实宿主启用、撤销和权限需求 |
| 统一路径导航 / 挂载 | 多类对象的定位确实成为使用障碍；范围读取仍无法合理解决 |
| 逻辑导出 / 跨产品迁移 | 用户提出可移植需求，能明确格式、权限映射、恢复范围和删除状态来源 |
| ANN、更多后端或分布式调度 | 实测容量、延迟或部署约束超过现有方案；不能只因竞品拥有就立项 |

Nowledge Mem 的个人 Spaces 组织方式不能替代 tenant/workspace 安全边界；实体/缓存/综合内容仍须经过 scope 与来源校验。[N9] 源码参考优先独立实现；TrueMemory 的 AGPL-3.0 标识意味着复制或依赖前需专项许可审查，本文不作法律结论。[T10]

# 10. 架构与接口：只增加必要职责

**总体结构保持模块化单体与既有持久化体系。** 下表是逻辑职责，不要求新增微服务、第二 Worker、第二事实库或第二套编排器。[O1] [O6]（§3）

| 位置 | 复用现有部分 | 本轮建议增量 |
| --- | --- | --- |
| 客户端 Connector | HTTP/CLI/MCP 接入方式 | 宿主版本和能力声明；原始消息适配；本地队列、重试与自检 |
| HTTP / Service | 认证、scope、幂等、任务受理、版本/来源校验 | 会话定位与消息追加；同步确认；授权的范围读取和诊断 |
| Session / 来源层 | 原始事件、文件、权限与来源管理 | 消息身份、修订/分支、采集策略、SessionTurn 聚合和反馈绑定 |
| Worker | 持久任务、重试、账本、最终提交检查 | 会话索引/提炼；显式 Improve；有条件 Learning；可选快照生成 |
| Retrieval / Resolve | 各检索分路、RRF、证据校验、预算与引用 | 可选 explain；评分语义；按实验证据增加重排和类型策略 |
| 上下文投影 | 既有 resolve 与规划中的 EvidenceBundle | 项目/任务工作快照、启动包预览、输入版本和来源失效控制 |

### 10.1 接口扩展原则

会话归档、消息追加、同步状态、按范围读取应有明确职责；它们不等于现有文本抽取 `/v1/captures`。启动上下文可以扩展现有 resolve 的策略，或由轻量上下文入口复用它；无论采用哪个入口，都不能复制授权和证据验证逻辑。

解释信息应为兼容性扩展或独立受控读取，不改变已有 score 的含义而不声明版本。写入型 MCP 工具若后续需要，应显式定义角色与幂等；不能因接入自动捕获就扩大当前只读工具权限。[O2] [O3]

### 10.2 先冻结四类边界

**身份边界：** 调用方凭据、被描述主体、外部会话和项目标识分别是什么；别名或路径不能授予跨 workspace 权限。

**状态边界：** 已受理、已持久化、已索引、已提炼、已发布分别意味着什么；断开连接与模型失败如何恢复。

**证据边界：** 原始消息与派生知识如何关联；retrieved/provided/cited 如何记录；来源撤回如何传播到快照、trace 和导出。

**兼容边界：** 新表与策略如何显式启用；旧库如何检测、安装或拒绝；不可在启动中静默升级或重新解释旧 fact_key。[O4]

# 11. 现有规划与融合后计划：差量落地

本表是**建议修改项**，不是仓库已经更新的执行承诺。保留原有阶段目标，只增加必要的交付细节与验收，避免功能膨胀。

| 阶段/任务包 | 原计划不变的部分 | 建议新增或改写的部分 | 不增加的范围 |
| --- | --- | --- | --- |
| **S1 / A 检索诊断** | 真实模型基线；100→300 题；同预算模式对照；摘要/图消融 | 分路、score_kind、过滤与预算原因；正确证据输入对照；根据失败位置选择重排实验 | 默认 HyDE、ANN、完整观测平台、生产发布拆分 |
| **S2 / B 语义规则** | 属性目录、单值/多值、稳定身份、冲突与歧义 | 数字/否定/纠正保护；断言状态；筛选/去重一致性；原文和关系溯源 | 第二版本系统、全部记忆类别、复杂本体、有效时间提前交付 |
| **S3 / C 会话输入** | SessionTurn、来源与作用域 | 消息 ID/修订/分支；持久化确认；一个连接器；范围读取；补传与失败 trace | 全客户端覆盖、模型代理、无限工具日志保留 |
| **S3 / D 经验闭环** | 幂等反馈、显式 Improve、水位、Learning 入库与复用 | 以 provided/cited/support_check 细化“使用证据”；提炼失败可重试且不丢原文 | 自动 Wiki、Skill、全部八阶段 Improve 同时实现 |
| **S4 / E 工作上下文** | EvidenceBundle、类型分路、冲突、预算、引用、Agent 对照 | 工作快照、启动包、预览；状态证据等级；来源失效与安全缓存 | 独立项目管理器、常驻自主知识 Agent、完整桌面端 |

### 11.1 依赖关系

A 保持当前主线；B 的语义契约和 C 的事件协议可提前设计。C 的原文保存不必等待所有语义算法完成；D 的发布与更新必须依赖必要的 B 和可靠的 C。E 使用 A 的检索证据与 C 的任务历史；涉及 Learning 的分路再接 D，不强制把所有可选增强都做完才提供启动上下文。

这意味着：**工作记忆的产品价值高，但不是把 S1/S2 跳过去的理由；另一方面，可靠捕获也不应被完整语义自动化无限阻塞。**

### 11.2 如何控制新增成本

已有规划中的会话、反馈、经验和统一证据，不再作为竞品借鉴重复统计。真正增加范围的主要是连接器及同步协议、任务启动快照、细粒度诊断；其余多数是原任务的契约和测试细化。估算工作量时只计算这些差量，并单列兼容升级、跨平台适配和模型实验成本。

原有安全与恢复演练并行推进。跨产品导出和展示界面暂缓，不抵销这些基础保障的责任。

# 12. 验收：证明有用，也证明没有破坏治理

不使用“和竞品一样有这个按钮”作为完成条件。先冻结测试集和阈值，再实施；发布门槛与平均质量分数分开。

| 维度 | 既有验收基础 | 本版建议补充 | 不可接受的结果 |
| --- | --- | --- | --- |
| 会话可靠性 | S3 要求问答归档和幂等 | 固定采集清单；尾部半行、轮转、重复事件、修订、断网补传 | 重试重复入库；来源记录缺失却报告完整 |
| 语义安全 | S2 的跨主体/条件/歧义反例 | 数字改变、否定、明确纠正、晚导入旧资料、多值补充 | 误覆盖、把提议当事实、纠正被高相似去重 |
| 检索质量 | S1 的 Recall、nDCG、Coverage、成本/延迟 | 候选覆盖与最终上下文分别测；分路归因与重排消融 | 用更大上下文预算伪装算法增益 |
| 经验复用 | S3 的显式 Improve→Learning→第二会话 | 学习样例与验证样例分离；保留条件和输入证据 | 无来源经验；重试制造重复；撤回后仍被使用 |
| 工作连续性 | S4 的真实 Agent 对照 | 继续任务成功率、重复说明量、过期状态误用、重复操作 | 把助手声称完成当成已验收；错误延续旧任务 |
| 安全与恢复 | scope、来源、版本、墓碑和恢复演练 | 快照、诊断、客户端队列及导出也纳入权限/清理测试 | 越权、泄露已撤回正文、旧缓存复活 |

### 12.1 三组对照定位改进来自哪里

**正确证据输入：** 向同一回答模型提供人工标注证据，测证据充分时的任务表现。

**实际检索输入：** 使用真实检索和预算组装，测召回、排序和裁剪损失。

**完整输入链路：** 从真实会话采集、归档、提炼、语义处理一路运行到回答，检查是否在写入阶段提前丢失信息。

对门控、摘要、图、重排和扩展分别消融；报告策略版本、语料 hash、模型、候选量、最终上下文预算、费用、延迟和失败分类。默认开启某项优化，必须同时满足质量收益、成本预算和安全回归，而不是只看平均分。

### 12.2 不拿竞品分数替代本项目验收

TrueMemory 的评测资料区分 Oracle/Strict、模型、top-k 和评判流程；这些差异足以改变答案正确率的含义。答案正确率也不是 Origence 的证据 Recall@k。本版不进行跨产品排名，亦不把独立检索实验结果当作自动捕获与提炼无损的证明。[T7] [T9]

规定回归集中的零越权、零错误覆盖是测试门槛，不是对所有现实输入绝对零风险的保证。任何豁免与未测场景应留在验证记录中。

# 13. 对原文与仓库规划的具体修订建议

### 13.1 对 v1.0 的收紧

| v1.0 表述或组合 | v2.0 修订 | 原因 |
| --- | --- | --- |
| E01–E07 多项统一归为核心吸收方向 | 区分真正新增、既有完善和实验候选 | 防止把已有规划再次统计为新增功能 |
| 工作记忆优先级最高 | 产品价值高；实现为 S4 投影，并依赖可靠历史与证据 | 避免跳过输入/质量基础，也避免建设第二事实库 |
| E07 基础索引与智能加工分离 | 评测开关先做，运行时发布拆分有条件实施 | 两者改动风险、兼容成本不同 |
| E08 综合与 Learning | Learning 必做，Crystal/Wiki 后置 | 前者已经是 P1，后者不是必要前置 |
| E11 导出与重建 | 导出可后置；备份恢复继续并行验收 | 可移植性与可恢复性不是一件事 |
| “实际使用证据” | 明确 retrieved/provided/cited/support_check | 不把可观测记录夸大为模型内部因果 |

### 13.2 仓库内需要澄清的旧表述

整体设计 §6.1 仍含候选截断可能漏召回的历史描述，而 STATUS 与身份规格已记录 S0 前置过滤修复；应标为历史，而不是据此重开修复。整体设计中的旧 Rust/验收状态也应指向 STATUS 的新快照。[O1] [O4] [O6]

整体设计 §8 列出八阶段 Improve，当前 S3 已缩小为显式经验提案、核验和发布；交付时以 S3 为准，不恢复全部阶段作为首版门槛。旧路由示例中的“会话命中可跳过图”不能演化为无条件跳过知识证据；应由较新的 I4/S4 类型与冲突契约明确策略。[O4] [O5] [O6]（§6、§8）

### 13.3 建议更新位置

**整体设计 §6–8：** 补诊断、事件归档与工作快照职责，收紧“使用证据”定义，保留模块化单体和非 Agent 执行边界。

**身份与上下文规格：** 增加数字/否定/纠正反例、断言状态、语义关系与快照来源失效；不改变已发布身份编码含义。

**S0–S4 路线图：** 按第 11 节只增补差量任务与完成条件；可选增强用独立触发条件，不进入默认必交清单。

**API / STATUS / VALIDATION：** 只有相应接口、实现和测试证据真正产生后才更新完成状态。本文生成不等于已修改这些文件，也不等于新阶段已验收。

**最终方向：从“可治理地存与查”，演进到“可靠接入真实工作、能解释记忆处理、能在有效证据上继续任务”。不以复制竞品的全部模块作为目标。**
